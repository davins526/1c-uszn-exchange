# Обмен УСЗН для 1С

Внешняя обработка для заполнения DBF-файлов обмена с Управлением социальной защиты населения (УСЗН) на основании данных информационной базы 1С.

Входящий файл содержит адреса. Обработка находит лицевые счета, заполняет показатели по услугам и сохраняет файл-ответ. Для баз одной конфигурации с разными названиями видов расчета предусмотрено автоматическое распознавание и настраиваемое сопоставление услуг.

## Задача

Номера договоров во входящем файле могут отличаться от номеров в базе. Поэтому лицевой счет определяется по улице, дому, корпусу и квартире или помещению. Если квартира не указана, рассматриваются лицевые счета дома. Автоматическое заполнение выполняется при единственном подходящем кандидате; неоднозначные адреса пропускаются с сообщением.

Одинаковые услуги могут называться по-разному: «Холодная вода», «Вода холодная», «ХВС», «ХВ». Обработка распознает распространенные названия, а соответствия сохраняет по ссылкам на виды расчета конкретной базы.

## Возможности

- Загрузка и сохранение DBF в кодировке OEM.
- Поиск лицевых счетов по адресу.
- Заполнение полей `SUM_N1`–`SUM_N16`, признаков договоров и показателей задолженности.
- Автоматическое сопоставление стандартных услуг категориям обмена.
- Настройка категорий услуг и автоматический пересчет после изменения.
- Категория «Не выгружать» для услуг, не участвующих в обмене.
- Сохранение настроек для пользователя базы и сброс к начальным правилам.
- Кэширование поиска по адресам домов и подготовка данных по нескольким лицевым счетам запросами.

## Технологии и зависимости

Платформа: **1С:Предприятие 8**. Язык: **BSL**. Интерфейс: **управляемая форма**, целевой клиент — **тонкий**. Работа с DBF выполняется через `XBase`.

Модуль зависит от метаданных конфигурации ЖКХ, в том числе:

- справочников `ркЛицевыеСчета`, `ркДома`, `ркУлицы`, `ркПомещения`, `ркВидыРасчетов`;
- регистров накопления `ркЗадолженностьЛицевыхСчетов`, `ркНачисления`, `ркОплата`;
- перечисления `ркТипыВидовРасчетов`.

Настройки адаптируют обработку к названиям услуг в базах одной конфигурации. Для другой конфигурации с иными метаданными потребуется изменить запросы и обращения к объектам.

## Содержимое

- `src/Module.bsl` — модуль формы внешней обработки.
- `docs/PUBLIC_VERSION.md` — сведения о подготовке публичной версии и границах проверки.
- `.gitignore` — исключение рабочих данных и локальных файлов из Git.
- `.gitattributes` — правила текстовых файлов и переводов строк.

В репозитории опубликован исходный модуль. Готовая `.epf`, описание формы и метаданные конфигурации в комплект не входят, поэтому модуль сам по себе не является запускаемой обработкой.

Для интеграции нужна управляемая форма с таблицей `ТаблицаФайла`, реквизитом `ПутьИсходногоФайла` и таблицей `НастройкиУслуг`. Поля входного файла перечислены в функции `ВсеПоляDBF()`; таблица дополнительно использует колонку `СсылкаНаЛС`. Таблица настроек содержит `ВидРасчета`, `ТипРасчета`, `КатегорияОбмена`, а элемент колонки категории называется `НастройкиУслугКатегорияОбмена`. Команды и события формы связываются с соответствующими обработчиками модуля.

## Порядок работы

После интеграции в совместимую обработку:

1. Загрузить входящий DBF.
2. Выполнить «Заполнить ЛС».
3. Выполнить «Заполнить суммы».
4. Проверить результат и при необходимости изменить категории в настройках услуг.
5. Сохранить файл-ответ.

Используемые услуги без категории требуют настройки. Если настройки изменены ошибочно, их можно сбросить к начальным правилам. Правила для отдельных адресов и периодов в публичную версию не включены — такие соответствия задаются через настройки услуг.

## Статус и проверка

Рабочая разработка передана на пользовательское тестирование. Эта копия подготовлена для публикации и изучения кода; отдельный запуск публичной версии в 1С не выполнялся.

Алгоритмы агрегирования сумм и определения задолженности сохранены. Перед практическим применением требуется проверить итоговые показатели по действующему соглашению обмена и данным тестовой базы.

## О проекте

Практический проект автоматизации обмена в 1С: чтение DBF, сопоставление адресов, запросы к регистрам, распределение показателей по услугам и пользовательские настройки. Публичный комплект содержит исходный код и документацию без рабочих файлов обмена и данных клиентов.
